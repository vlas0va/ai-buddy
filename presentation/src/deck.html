Hack&Change 2026 · кейс Авито «AI-buddy»

AI-buddy — ИИ-наставник, который ведёт стажёра по адаптации и учит, а не делает за него

План из чек-листа Авито, ответы со ссылкой на источник, отгул и доступы через сервисы компании — а наставник отвечает на вопросы раз в день, и каждый ответ пополняет базу знаний.

Команда Halcyon: Власова Маргарита, Кожакина Анна, Корочкина Елизавета

Запуск у себя: make up (нужен только Docker) → localhost:5173, ключ LLM не нужен

Проблема

Наставник тратит 40–48 часов за стажировку на повторяющиеся вопросы, а стажёр теряет дни на оргвопросах и инженерном онбординге

40–48 ч

тратит наставник за шестимесячную программу, 55–65 ч — за девятимесячную

16 шагов

чек-листа стажёра в пяти периодах — от первой недели до выпускного

3 роли

в одном отгуле: руководитель, HR-администратор, HR BP — стажёр не знает порядок

Что болит у стажёра

  • Инженерный онбординг: Bitbucket и SSH, ветки и PR, кого звать на ревью, CI/CD, секреты, стенд
  • Оргвопросы требуют конкретики: где и когда ноутбук, куда писать, в каком порядке оформить отгул
  • Соблазн отдать задачу нейросети и вставить ответ, не разобравшись

Ограничения, которые задаёт кейс

  • Не показывать чужие данные и не выполнять чужие операции
  • Зарплата, выплаты, медицина — только к HR BP; денежных операций нет
  • Не заменять людей: 1:1, обратная связь, экватор — за наставником
Источник цифр: материалы кейса Авито2
Решение · чем отличается от очевидного варианта

Не «чат-бот по wiki»: заявки ведут проверяемые сценарии, LLM отвечает только по найденным документам, а наставника buddy не дёргает

Сквозной сценарий · S3 отгул

Отгул — одно сообщение и одна кнопка вместо поиска инструкции и писем трём людям; статус стажёр видит в чате и в плане

«Как оформить отгул?» — порядок и источник
Дата в календаре
Проверка правил, черновик
«Отправить» → ABS-…
Руководитель видит, кто ещё отсутствует
HR-администратор оформляет
Статус у стажёра

Было: найти инструкцию, понять порядок, написать руководителю и наставнику, создать заявку в сервисе отсутствий, проверять статус. Неполный запрос («хочу отгул» без даты) — buddy открывает календарь; дата в прошлом или выходной — объясняет и не создаёт черновик. Отказ — заявка уходит из плана, причина видна в «Моих заявках».

Заявку создаёт сервис отсутствий (absence MCP) только после подтверждения; повтор не создаёт дубль; заявку можно перенести или отозвать4

S2 · вопросы и нестандартные ситуации

Если ответа нет в базе знаний, buddy не выдумывает: говорит об этом, даёт текст для наставника и ставит вопрос в его список

Как buddy понимает, что информации мало

Документ ищется только среди доступных роли и команде; ответ даётся, если документ прошёл порог релевантности BM25 и покрывает значимые слова вопроса (доля по IDF). Совпадение только по общим словам («работа», «команда») — это «не знаю».

СитуацияЧто делает buddy
Вопрос не по темеВежливо возвращает к адаптации
Чужие данные, зарплатаОтказ и к кому идти (HR BP)
«Игнорируй инструкции»Отказ, промпт не раскрывает
Лог с паролемСкрывает секрет, разбирает ошибку

Ответ наставника «всем стажёрам» попадает в базу знаний: следующий стажёр, даже из другой команды, получает его с пометкой «Ответ наставника».

Каждый ответ по базе — с источником и плашкой «Тестовая инструкция прототипа»; «Полезно / Не полезно» под ответом — метрика качества6
Наставник и руководитель

Наставник видит пользу buddy в цифрах — долю вопросов без него и сэкономленные минуты — и готовый отчёт к встрече 1:1

«Польза buddy» считается по журналу: вопросы, закрытые buddy сам, эскалации, ответы в базу знаний, оценки «Полезно». Минуты — по нормативу на один вопрос. Цифры на скриншотах — из демо-данных.

Только стажёры своей команды — фильтрует сервер; руководитель согласует заявки и видит отсутствующих в те же дни7
Техническая реализация

Агент подключается к сервисам компании через MCP от имени пользователя, поэтому новая система добавляется без изменения агента

web (React, SSE)
   │
core (Go): REST, план, журнал, JWT, флаги, AI-cron
   │
agent (Python): роутер → сценарии · RAG с ACL · LLM
   │  MCP · streamable HTTP · JWT пользователя
   ▼
absence · access · directory · kb · approvals
checklist · trips · consents      (8 MCP-серверов)
  • Один конфиг agent.yaml: промпт, модель, MCP-серверы, инструменты по ролям
  • Привычный стек: Go и Python, как в бэкенде Авито; сервисы в контейнерах с healthcheck
  • Свои мощности: A-Vibe (AvitoTech/avibe) через vLLM или Ollama; любой OpenAI-совместимый API — одной переменной
  • Пилот по командам: runtime-флаги, стоп-кран за минуту; события core → Kafka

Пять рубежей: ошибка модели не превращается в утечку

1
Guardrails до LLM — чужие данные, зарплата, медицина, prompt injection
2
Документы по правам — ACL до ранжирования и повторная проверка в агенте
3
Инструменты по ролям; пишущих инструментов модель не видит
4
Проверка в сервисе — каждый вызов с JWT пользователя
5
Подтверждённая запись — HMAC-токен связывает пользователя и аргументы; повтор не создаёт дубль
Моки Confluence, Jira, Bitbucket и кадровых сервисов заменяются реальными MCP-серверами; данные синтетические, без ПДн и денежных операций8

Ценность и внедрение

Ожидаемый эффект — минус 30% рутинных обращений к наставнику; проверим его пилотом по командам, а не обещаем заранее

Гипотеза: если стажёр получает ответы и оформляет заявки в одном чате по своему плану, рутинных обращений к наставнику станет меньше, потому что ответы берутся из базы знаний и сервисов, а каждый ответ наставника пополняет базу.

МетрикаЦель пилота
North Star: время до первой самостоятельной задачи−20% к контролю
Рутинные обращения к наставнику−30%, ≥ 8 ч из 40–48 за программу
Вопросы без эскалации / «Полезно»≥ 70% / ≥ 80%

Как внедрить

  • Подключить реальные MCP к Confluence, Jira, Bitbucket и кадровым сервисам — агент не меняется
  • A-Vibe на собственных GPU (vLLM), без внешних API
  • Включить флагом для части команд; difference-in-differences к контролю и прошлой когорте
  • Метрики уже пишутся: события core → Kafka → дашборд; сбой guard-метрик — флаг выключается
Цифры пилота — гипотеза для проверки; в прототипе измеряются те же показатели («Польза buddy»). Подробно: docs/product/metrics.md11
