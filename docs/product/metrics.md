# Метрики пользы и пилот AI-buddy (R06, R24, R25)

Владелец: A. Источник событий — `contracts/events.md` (B), дашборд — Grafana на `core.analytics_events`.

## Зачем мерить
По оценке Авито наставник тратит **40–48 ч** за шестимесячную программу и **55–65 ч** за девятимесячную (R06). AI-buddy должен
снимать рутину (оргвопросы, доступы, отгулы, поиск документов), не трогая содержательную работу: 1:1, обратную связь, ревью
компетенций, экватор и выпускной. Поэтому главная метрика — скорость выхода стажёра на самостоятельную работу, а защитные
метрики следят, чтобы ускорение не купили ценой качества и безопасности.

## Дерево метрик
| Уровень | Метрика | Как считаем | Событие-источник | Цель пилота |
|---|---|---|---|---|
| Главная (North Star) | Время до первой самостоятельной задачи, дни | от `cohort_start` до `plan.task_done` задачи «первая задача» | `plan.task_done` | −20% к контролю |
| Эффект для наставника | Рутинные обращения к наставнику на стажёра в неделю | эскалации из чата + дневник наставника 2 недели | `chat.escalated` | −30% |
| Эффект для наставника | Сэкономленные часы наставника за программу | (обращения контроль − пилот) × медианное время ответа | дневник + `chat.escalated` | ≥ 8 ч из 40–48 |
| Качество ответов | Доля вопросов без эскалации | `chat.answered` / (`chat.answered` + `chat.escalated`) | `chat.answered`, `chat.escalated` | ≥ 70% |
| Качество ответов | Доля оценок «полезно» | `chat.feedback{useful}` | `chat.feedback` | ≥ 80% |
| Снятие рутины | Успешные действия с первой попытки | `action.created{attempt=1}` / все действия | `action.created`, `action.failed` | ≥ 95% |
| Снятие рутины | Время от намерения до заявки, медиана | `action.created.duration_ms_since_proposal` | `action.proposed`, `action.created` | < 2 мин |
| Дисциплина адаптации | Доля шагов чек-листа в срок | `plan.task_done{on_time}` / все шаги периода | `plan.task_done`, `plan.task_overdue` | +15 п. п. |
| Точка входа | Использование после выпускного | недельные сессии роли `alumni` | `session.started` | ≥ 30% выпускников |
| Защитная | Корректные отказы вне прав и по ПДн | guard-кейсы eval + `chat.refused` на ручной разметке | eval, `chat.refused` | **100%** |
| Защитная | Ошибки на эталонном наборе | `make eval`, отчёт `eval/reports/latest.md` | eval | 0 в guard, ≥ 95% всего |
| Защитная | p95 отклика UI на локальные действия | `ui.task_toggle.latency_ms` | clickstream | < 1 с (R76) |
| Защитная | p95 первого события чата | `done.latency_ms` агента, `status` < 100 мс | `chat.answered` | < 1 с до `status` |

В прототипе все эти события уже пишутся (core → Kafka/outbox → `analytics_events`), а агент отдаёт в `done` поля `intent`,
`provider`, `latency_ms`, `escalated`, `tool_calls` и `prompt_version` — по ним считаются качество и стоимость.

## Как проверить эффект на стажёрах
1. **Дизайн.** Пилот на одной когорте; включение через runtime feature flag `scenario_s1..s4` **по командам**, а не по людям:
   внутри команды стажёры общаются, и советы «перетекали» бы в контроль. Команды случайно делим на пилот и контроль со
   стратификацией по размеру и направлению (backend, ML, продукт).
2. **Сравнение.** Difference-in-differences: (пилот − контроль) в этой когорте минус (те же команды − контроль) в прошлой
   когорте — снимает различия между командами и сезонность.
3. **Опросы.** Короткая анкета стажёров и наставников на 2-й неделе и на экваторе (5 вопросов, шкала 1–5) и дневник времени
   наставника в течение двух недель — источник «сэкономленных часов».
4. **Статистика малых когорт.** Когорты маленькие, поэтому сначала смотрим метрики с большим числом событий (обращения,
   заявки, ответы), считаем бутстреп-доверительные интервалы по командам; решение о раскатке — после экватора.
5. **Стоп-критерии.** Любой сбой guard-метрик (утечка чужих данных, ответ про зарплату) — флаг выключается для всех команд
   за минуту (`PUT /api/flags/{key}`), инцидент разбирается до повторного включения.
6. **Раскатка.** Пилот 1 когорта → все команды направления → все стажёры; затем — точка входа для выпускников (R58).

## Как это видно в прототипе
- Grafana-дашборд (профиль `full`) строится из `analytics_events` на синтетических данных.
- `make eval` — 92 кейса, guard-метрики 100% (`eval/reports/latest.md`); классификатор — `eval/reports/intents.md`.
- `/metrics` агента: `agent_turns_total{intent,source}`, `agent_refusals_total{reason}`, `agent_actions_total{kind,outcome}`,
  `agent_errors_total{code}`, гистограммы `agent_turn_seconds` и `agent_execute_seconds`.
