# ADR-006. SSE вместо WebSocket для чата

Статус: принято · Владельцы: A, B, C · Требования: R77, R78, R79

## Решение
Ответ агента — однонаправленный поток событий (`status`, `token`, `sources`, `action_proposal`, … `done`) по SSE.
Действия пользователя (подтвердить, повторить, оценить) — обычные REST-запросы.

## Почему
- Поток нужен только сервер → клиент; SSE работает поверх HTTP/1.1, проходит прокси, легко проксируется core (Go) и
  тестируется curl-ом.
- Нет состояния соединения: обрыв = повтор запроса с тем же `message_id`, сервер отвечает идемпотентно.
- Статусы ожидания (`status`) приходят в первые 100 мс — интерфейс не блокируется, даже если LLM думает 10 секунд.
