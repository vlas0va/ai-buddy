# ADR-007. Гибридный агент: детерминированные сценарии записи + LLM для языка

Статус: принято · Владелец: A · Требования: R04, R15, R17, R66, R71, R79

## Контекст
Чистый «LLM с инструментами» гибок, но на демо и на слабой локальной модели может перепутать даты, вызвать не тот инструмент
или забыть про подтверждение. Для пишущих операций это неприемлемо.

## Решение
1. **Роутер намерений** (правила высокой точности → обученный классификатор → порог уверенности) определяет намерение:
   `absence`, `access`, `channels`, `plan`, `approvals`, `kb_question`, `whois`, `escalate`, `smalltalk`, а также отказы.
2. **Сценарии записи** (S3 отгул, S4 доступы, согласование руководителя) — конечные автоматы со слотами и валидацией.
   Они одинаковы для stub и LLM. Результат — `action_proposal`; запись — только после подтверждения через `/execute`.
3. **LLM** используется там, где важен язык: ответы по базе знаний (S2) с обязательной опорой на найденные документы,
   формулировка напоминаний и сводок. В режиме `openai_compat` LLM может вызывать **только читающие** инструменты своей роли
   (function calling, не более `max_tool_iterations` шагов).
4. Каждый ответ по базе знаний несёт источники и плашку «Тестовая инструкция прототипа».

## Последствия
- Предсказуемость и безопасность пишущих сценариев не зависят от модели.
- Добавление нового корпоративного действия = новый MCP-инструмент + конечный автомат + eval-кейсы (скилл `add-agent-tool`).
