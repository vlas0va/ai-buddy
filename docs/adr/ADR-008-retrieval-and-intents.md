# ADR-008. Поиск по базе знаний и классификатор намерений

Статус: принято · Владелец: A · Требования: R02, R15, R69, R71

## Поиск
- Базовый вариант — BM25 со стеммингом Snowball (русский) по заголовку и абзацам документа; ACL-фильтр по роли и команде
  применяется **до** ранжирования. В compose тот же поиск выполняет mcp-kb (PostgreSQL FTS `russian`), агент повторно сверяет ACL.
- Опционально — гибрид BM25 + эмбеддинги (любой OpenAI-совместимый `/embeddings`, например `bge-m3` в Ollama), слияние RRF.
- Порог релевантности (`min_score`) и покрытие запроса (`min_coverage`: IDF-взвешенная доля слов вопроса, найденных в
  документе): если документ совпал только по общим словам («работа», «команда»), buddy честно говорит «не нашёл» и
  предлагает черновик наставнику, а не отвечает невпопад.
- Контекст пользователя (команда, этап, открытые задачи) поднимает документы своей команды и текущего периода.

## Классификатор намерений
- Мультиномиальная логистическая регрессия (softmax) на стеммах слов и символьных 3–4-граммах, чистый Python, без тяжёлых
  зависимостей, фиксированный seed. Наивный Байес оставлен как базовая линия в отчёте (на кросс-валидации он хуже на ~5 п. п.).
- Обучается скриптом `services/agent/training/train_intents.py` на `eval/intents/train.yaml` за секунды; модель —
  JSON в репозитории (`agent/models/intent_model.json`), отчёт качества — `eval/reports/intents.md`: 5-fold CV и точность
  на отложенном наборе `eval/intents/test.yaml` (фразы, которых нет в обучении) — отдельно для классификатора и для всего роутера.
- Перед классификатором — guardrails и правила высокой точности, после — порог уверенности и запасной путь `kb_question`.
  Пишущие сценарии (отгул, доступы, согласования) классификатор запускает только при уверенности ≥ 0,6 — обычные формулировки
  ловят правила, поэтому ошибка модели в худшем случае превращается в ответ по базе знаний, а не в черновик заявки.
- Датасет можно расширить парафразами от локальной LLM (`training/augment_with_llm.py`, Ollama) и переобучить.
